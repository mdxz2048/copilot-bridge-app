# 0.3.28 联系管理员与邮件草稿

账户页、设置页和应用错误提示新增可点击的 `zhipeng2048@gmail.com`。点击通过限定的 support:compose IPC 打开默认邮件应用的新邮件草稿，收件人固定，不接收任意 URL、收件人或附件参数，也不会自动发送。官方客户端收到的模型错误文字保留可复制邮箱；本次没有修改官方客户端自己的错误界面。

主进程为当前登录用户生成草稿，预填用户 ID、发生时间（北京时间）、版本、错误码和错误内容。最近的模型故障还带请求 ID 与诊断 ID。主进程仅在内存保留最近一次错误元数据，不携带请求、工具输入输出或会话正文；切换账号不会读取其他用户的错误。未登录或当前进程尚无错误时明确显示暂无记录，不伪造用户 ID 或时间。应用自身的错误提示可以把当时显示的错误传给草稿；与当前模型错误不同的提示不混入模型请求 ID。

错误文本通过既有脱敏函数去除密码、令牌等敏感内容，修复截断 Unicode 代理项导致 mailto 编码失败的问题。邮件 URI 控制在 Windows 邮件处理器可接受的保守长度内，过长错误截短并标记；元数据保留。系统没有可用邮件应用时显示复制邮箱的反馈。FailureCapture 的发生时间改为实际记录失败时的时间，而非请求开始时的时间。

## DEVICE_PROOF_INVALID 排查

15:35 和 15:37 两次历史模型 POST 在鉴权阶段返回401，同设备账户轮询和失败报告上传成功。用户随后确认同会话重试已恢复正常。旧日志没有细分失败项，不能据此判定是设备密钥、请求体摘要、目标地址还是签名时效问题，也不能把恢复描述为已经定位并修复根因。

服务端已新增不含令牌、DPoP、密钥、正文或正文哈希的校验失败原因日志，保留签名、60秒时效、目标地址、令牌绑定、原始正文绑定及防重放规则。设备校验错误文字明确给出管理员邮箱，没有增加自动重放模型请求，也没有放宽校验。
